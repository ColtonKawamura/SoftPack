# T-196b: the HDF5 schema

*Up:* [Design decisions](index.md)

**Question.** `write_packing()` could not be written: only three dataset names were
decided, and the default file was described both as "remaining particles only" and as
"full restart state".

**Choice.** The main groups hold the remaining particles and their contacts. A `state`
group holds every particle and the full dynamic state, which is what a restart reads; the
same file can therefore be both a result and a checkpoint. The file records the version,
the commit, the Julia version, the seed, the RNG and its version, and the settings as
TOML. `particles/id` is 0-based, and every dataset is 1-D.

**Why.** One file that is both the result and the checkpoint means a user does not have to
remember to save twice, and the rattler rule stays a view: the particles are still there
in `state` even when the main groups hold only the backbone.

**Status.** In code; the schema table is on the [`write_packing` path page](../write_packing/path.md).
