# T-s698: the cone test in 3D, the backbone, custom rules

*Up:* [Design decisions](index.md)

**Question.** Three smaller rattler questions: what the cone test does for a
three-contact sphere, whether a run checks that the remaining backbone is rigid, and what
a user rule receives.

**Choice.** The cone test stays two-dimensional and applies to two-contact particles; the
3D gap is documented rather than guessed, because a three-contact sphere needs a
tetrahedron or a linear-program check, which is a separate algorithm. A run warns when
the remaining backbone is hypostatic, comparing its coordination with the isostatic value.
A user rule receives the `Packing`, which carries the contact table (pairs, normals,
forces) and the `converged` flag — a superset of the struct the card proposed.

**Why.** A warning about a hypostatic backbone catches the case where a rule removed so
much that the packing is no longer rigid, which is otherwise invisible in the output. The
`Packing` argument was already public and documented, so defining a second, narrower
struct would have added a type without adding information.

**Status.** In code (warning in `finish_packing`); the 3D cone test is not implemented.
