# T-c822: validation and errors

*Up:* [Design decisions](index.md)

**Question.** Many keywords had no stated range or error behaviour, and
`failure_action = :error` contradicted the promise that `pack()` never throws a packing
away.

**Choice.** A bad value throws an `ArgumentError` that names the keyword. A restart
refuses any keyword outside the run-control list, even one equal to the stored value.
`failure_action = :error` throws a `PackingError` whose `packing` field holds the
unfinished `Packing`, so catching the error still gives you the state.

**Why.** An error that names the keyword can be fixed without reading the source, and an
error that carries the packing keeps the promise: the run's work is not lost, it is
handed over with the exception. The alternative — clamping a value with a warning —
silently changes the physics the user asked for.

**Status.** In code. Not implemented: an error for a keyword that has no effect in the
chosen combination (it needs a table of which keywords matter when), and a friendly error
for `pack(params; keyword = ...)` (Julia raises a `MethodError` first).
